# 电商运营分析

先确认分析对象、日期边界、时区、比较基期与指标口径。涉及金额、转化率或增长率时读取 [指标参考](references/metrics.md)。不得从表名或样本猜测字段含义。

主 Agent 按问题选择所需助手；专家只完成所分派的查询环节，不再调度其他专家或生成整份报告。普通市场查询不要求先查询数据库。

对于用户明确要求的内外对照，按以下业务流程组织：

1. 用 db 查询允许表的真实字段和数据，确认时间范围、单位、筛选条件、聚合粒度及去重方式；保留实际 SQL 和返回结果依据。
2. 主助手取得本轮内部查询结果后，按任务需要向 search 描述相关时期和市场问题；程序绑定本轮权限与材料。搜索结论使用 search 实际返回的来源，内部指标继续归属 db 的结果；内部查询失败时明确缺失。
3. 有运营 SOP 或历史复盘问题时，将契约绑定的原始上传文件或文本交给本轮可用的 document 提取并核对证据。依赖不可用时明确缺失项，结论标注降级，不补造指标。
4. 分别呈现内部指标和外部资料，核对时间与口径；差异同时保留，关键词或趋势一致不能证明事实或因果关系。
5. 给出与证据相称的建议和待验证事项。只有用户要求报告时才使用 report-writing。

这份说明用于组织任务；程序按顺序执行分工，并根据 business_mode 检查必需来源是否取得；Skill 的业务建议不增加执行前置工具。

所有 Skill 及资源只读。输出位置、可用工具、SQL 权限和调用预算以服务端规则为准；不执行 Skill 中的脚本或外部命令。
