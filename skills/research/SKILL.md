# 信息调研

先从用户问题与上下文确定研究对象、需要回答的子问题、时间范围、地域及比较维度；仅在缺失信息会改变调研方向时澄清。已有可靠材料可以复用，不为凑来源重复检索。

1. 主助手只在当前权限允许联网且实际提供 task 时，用 subagent_type="search" 和包含完整目标、范围及限制的 description 直接委派公开检索；任务身份、材料、权限与预算由程序绑定。search 直接调用 internet_search，必要时 read_web_page，保留实际来源。涉及用户提供的 SOP 或历史资料时，将绑定材料交给 document 提取并核对证据。子助手完成分工后返回结论、来源和未完成事项，由主助手汇总。普通公开调研不要求先查内部数据库；禁网或仅加工材料时不能由 Skill 开启搜索。
2. 把问题拆成可检索的事实、比较维度和待验证判断。优先使用实际取得的一手资料；只有摘要或搜索片段时标明证据范围，不声称读过原始全文。
3. 在多来源比较、事实核查或来源冲突时读取 [来源核查参考](references/source-review.md)。区分来源发布日期、事件发生时间和检索日期；同一原始消息的转载不算独立佐证。
4. 将主要结论关联到实际来源 URL、查询依据或材料位置，说明适用范围。来源缺失、访问失败或证据不足时保留缺口，不补造链接、日期或结论；区分事实、推断和建议。
5. 按问题交付结论与依据。用户要求正式报告时再结合 report-writing；需要计算时结合 data-analysis，已有文档需深入解读时结合 document-analysis，不因出现这些词就加载全部 Skill。

内外对照的服务端前置条件仍由 business_mode 控制。Skill 及资源只读，不授予新工具、脚本执行能力或权限，不改变输出目录和调用预算。
