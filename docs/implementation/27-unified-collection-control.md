## 执行规则

| 类型 | 行为 |
| --- | --- |
| `HookRejected` | 参数、权限或其他可纠正拒绝，返回脱敏的工具错误消息。 |
| `CollectionFinished` | 结束当前专家采集，保留实际证据，进入独立、无工具的报告步骤。 |
| `ExecutionTerminated` | 运行终止；预算耗尽、执行基础配置损坏和运行停止均不得转换为审核结果或模型反馈。 |
| `DependencyUnavailable` | 数据库允许表或只读凭据、Tavily 密钥、文件解析依赖缺失，结束对应专家分支；主助手直接调用时返回脱敏的工具错误。 |
| `ReservationUnavailable` | 尚未消费的报告或可选修订预留未获准，不等同于已消费的全局硬预算耗尽。 |

依赖异常必须在发生处显式区分，不能根据错误消息的关键词判断。`MissingConfiguration` 仅用于无法继续受控执行的基础配置（运行策略、模型配置、采集状态、必选技能、审计传输等）；具体业务依赖使用 `DependencyUnavailable`。研究入口和工具中间件将后者传递到所属专家边界，不交回该专家模型重试，不继续生成报告或调用审核。专家保存 `dependency_unavailable`、脱敏原因和失败子任务；主助手能够读取该状态。失败结果不发布、不计作已审核事实；缺失来源不得记为已覆盖。已审核的部分结果与真实缺口可以正常交付，运行结束状态与需求覆盖状态分开记录。保留项目已有、明确声明的 `internal_external` 依赖不可用流程，不增加替代数据源或执行路径。

终止标记由运行上下文持有。即使框架内部捕获过异常，下一次资源准入也会拒绝继续执行。工具、研究适配器、专家、计划回滚和审核边界均保留控制信号。

搜索、文档、数据库专家统一安装采集控制。搜索自己的动作协议和搜索/网页额度仍由搜索适配器负责；重复的搜索专用通用收尾逻辑已移除。

`config/runtime.yml` 新增 `collection.model_calls` 与 `collection.tool_calls`，默认均为 12，作用于每个专家任务。计数与全局预算在同一锁内准入，跨该任务的证据修订保留，不计入后续独立报告及审核调用。工具额度用尽后，采集模型也不会再发起下一轮请求。

采集结束不表示需求已经完成。报告仅使用已有真实证据，并保留缺口。局部采集结束不会自动终止整轮任务；全局硬预算耗尽则停止运行。

异步采集超时只包围采集阶段。结束或中断时清理该采集范围内仍在运行的异步工具调用，再进入报告；用户取消不转成正常采集结束。已发送的外部请求不被宣称为已回滚。

主助手的预算收尾不再依赖已经出现搜索结果或已审核内部结果。停止原因以 `collection_stopped` 事件记录；被采集控制挡住的工具不会被记录为成功执行的证据。

## 已进行的验证

未调用真实业务模型、搜索服务或数据库。未新增或修改测试文件；临时执行验证脚本未写入仓库。

使用现有脚本模型及生产专家工厂进行了临时执行验证：

- 同步、异步工具上限：只执行额度内的工具，随后生成报告；不再多发一轮采集模型请求。
- 同步、异步模型上限：停止采集，报告仍能独立执行。
- 同步、异步同批多工具越界：没有超过工具上限，进入报告前完成清理。
- 数据库缺少配置：该项最初错误地设为全局 `MissingConfiguration`；已在下述继续修复中纠正为分支 `DependencyUnavailable`，原验证结论不再适用。

- 外部取消及先标记运行取消后再取消任务：均传播 `CancelledError`，不生成报告，恢复作用域，释放专家预留。
- 硬终止检查点：拒绝恢复采样，原文件保留。
- 主助手尚无搜索或已审核结果时达到预算阈值：关闭采集、移除工具并进入结构化收尾。

## 继续修复：依赖错误的影响范围

最初实现将全部配置缺失当成全局终止，截断了项目已有的依赖不可用结果流程。本次在错误源头和专家执行边界修正，不放宽权限、SQL 约束、预算或证据审核。全局致命错误在直接专家入口也会设置终止标记。

修改前源码使用仓库外只读导入映射复现：同步、异步均在数据库凭据缺失后抛出全局异常，独立专家未执行。相同生产专家工厂和真实工具中间件下，修改后完成 16 项临时执行边界检查：

- 数据库凭据缺失、允许表未配置、搜索密钥缺失，分别检查同步和异步，共 6 项：失败分支仅调用一次采集模型，无报告/审核调用；未连接数据库或搜索服务；失败状态和原因落库且不发布；独立专家的工具、结构化报告和语义审核照常完成；缺失来源为必需项时，当时的最终门槛仍拒绝结束；这一行为未覆盖 API 正常交付，已由下述 2026-10-26 修复替代。
- 全局运行配置错误、已耗尽预算下的报告准入、单专家工具上限、单专家模型上限，分别检查同步和异步，共 8 项：前两类终止并锁定运行；后两类结束采集，报告与审核继续。致命状态的检查点拒绝恢复采样，保留原文件。
- 外部取消：保留 `CancelledError`，不发报告/审核请求，清理作用域、预留及执行槽。
- 主助手直接调用未配置数据库的同步/异步入口、文件解析依赖缺失和损坏运行配置的组合检查：验证局部反馈、分支依赖异常与全局异常互不混淆。

所有验证均使用固定协议响应驱动真实执行链和临时数据目录，不调用真实业务模型，不评价模型常识问答能力。没有新增或修改测试文件，也没有启动三道业务验收题。

## 2026-10-26：来源缺口贯通到最终交付与 API

Codex 没有本项目的 required_sources 业务验收器；以下来源核验、覆盖状态和文件一致性机制是对本项目的适配，不宣称为上游同名实现。

当前规则：

1. 最终渲染前，从本轮、当前所有者的持久化结果重建来源及必读文件状态，不相信模型声称的完成情况。
2. 程序把真实来源缺口附到正文，连同事实和分析一起终审。原始需求缺口仍使用 requirement_ids 渲染，不伪造事实或把缺口改为 covered。
3. 只有通过终审、绑定同一来源状态的正文，才允许通过缺口状态下的文件交付入口。Markdown 正文摘要、实际 CRLF 文件摘要，以及最终含下载链接的答复摘要分别校验。
4. API 允许已审核的部分结果正常结束：status=completed，coverage=partial 或 unknown；来源齐全且需求通过时仍为 complete。没有合格事实时交付未核实需求和来源阻塞说明，不产生无依据结论。
5. 真实性拒绝、文件或答复被替换、运行配置损坏、硬预算耗尽、取消和存储异常仍保留原有拒绝或终止行为，没有在 API 中捕获异常后强改成功。
6. 结果事件携带真实 source_status，现有前端根据 coverage 显示部分完成或覆盖待确认。未新增生命周期状态或改动身份认证。
