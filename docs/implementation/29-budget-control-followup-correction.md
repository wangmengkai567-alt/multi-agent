# 顺序②后续修正：计划额度、连续分工与请求时限

实施日期：2026-10-26。

## 问题与修复

1. 研究计划创建和封存曾与采集争抢普通工具额度。现在契约准入时分别为 plan_research initialize / seal 保留一次主模型和一次工具调用；只有操作、计划版本及阶段匹配时才能消费，append 不能挪用封存额度。连同必需分支和交付无法容纳时，在锁定契约前拒绝。
2. 旧实现把来源直接当作唯一工作身份，第一次文档或数据库分工完成后，同一专家的其他合法分工会被误拒绝。现在以专家与去除首尾空白后的完整描述建立持久工作身份；不同工作重新准入，同一工作不得重放刷新额度。新工作共享原整轮累计计数。恢复仅能一次性接管未消费预留，随后并发重入仍被拒绝。
3. 固定 10 秒时片会提前截断原本允许 60 秒的报告请求，并把所有未开始分支和可选修订的时间相加。已删除两项时片配置；模型与工具沿用配置上限，按整轮剩余时间扣除已启动专家的报告、审核以及终稿必要步骤。调用额度与时间分开核算；专家启动、可选修订、排队及重试继续受时间准入约束。

关键实现位于 agent/runtime/capacity.py、delegation.py、reservations.py、collection.py、governance.py、checkpoints.py、context.py 和 policies.py。
