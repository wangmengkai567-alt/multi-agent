# 跨问题可靠性修复与验收

用户要求换问题后仍能可靠执行，不能只针对武汉天气或手表型号修补。本文区分应用执行正确、最终答复完整，以及外部模型/搜索失败；不承诺模型永不出错。

## 已确认的共用缺陷

- 单对象检查被完整对比需求污染，修订查错对象；按实际 delegated_task 验收，user_query 只约束目的和范围。
- 搜索响应先按单条截断，再使用已截断副本分配总上下文，可能把中段关键事实再次删掉。现在从原始响应重新选片段，按实际查询词优先保留相关上下文；单条和总长度上限都不变。原始工具响应保持不变，截断仍明确标注。
- 搜索返回空列表仍被当成已取得来源，导致保留补查没有启用；按真实来源判断是否允许内容补查。
- 主助手可跳过实际工具，引用记忆中的网页甚至编造原文；最终答复现在核对本轮通过检查的真实证据，最多纠正一次。
- 纠正无证据草稿时，模型转去核验草稿十余条链接及 HTTP 状态；纠正上下文现在丢弃草稿，回到原始问题的必要范围。
- 域名过滤数组在部分兼容传参中被序列化为 JSON 字符串；现兼容合法数组编码并保持原有域名和类型检查。未执行的参数错误只有在后续同名工具真实成功后才解除阻断；没有后续成功、权限错误和实际执行失败仍阻断，历史错误记录不删除。
- 检查 JSON 格式不稳定、最终检查没有真实日期与星期；启用当前提供商已实测支持的严格 JSON Schema，向检查器提供运行参考时间和程序计算的日历。
- 失败后再次调用同一模型整理结果，仍可能超时或回显内部 JSON；连续失败的收尾改为程序生成，只保留通过检查的资料及粗粒度缺口。
- 模型思考前缀可能出现在普通输出；所有模型返回边界统一隔离已识别的推理包裹，不删除普通代码中的字面示例。
- 链接识别曾把紧邻 URL 的中文括号或 JSON 转义字符吞进地址；按真实文本边界提取，不把普通示例代码当来源。
- 指定官方来源的查询可使用 include_domains 将域名过滤实际传给搜索服务，特定版本另用路径定向查询；保留实际请求参数和原始返回。
- 单个真链接曾能掩护额外的假链接；现在全部引用均需可追溯，同一真实页面的片段锚点可以不同。
- 曾把子助手调用前超时、整理超时和搜索超时混称；分别保留阶段与原因，不把没有发起的检索描述成已经完成。

## 执行边界

普通检索任务初查 2 次，检查确认缺口后可用保留补查 2 次。普通轮次最多 3 个检索任务、总计 12 次实际检索；启用信息调研等复杂任务 Skill 时为每任务初查 6 次、整轮 24 次。重试不刷新槽位，额度拦截不执行服务调用，已接纳的并发请求仍可完成。主助手和子助手均有调用预算；总时限 300 秒、模型请求 60 秒、搜索请求 20 秒不延长。

通过检查的数据库资料与检索资料均进入最终检查上下文，避免只收集网页证据而丢失内部查询结果。

检查格式错误只重试检查，不重跑检索。最终文字检查最多纠正一次；有已通过检查的检索资料时，仅修订文字，不为润色重启搜索。仍不能可靠回答时返回有限结果，不把被拒绝的草稿、检查器猜测或超时任务的内容充当事实。

最终检查分别记录 complete 和 partial。先前尝试失败但后续已经可靠覆盖原始问题，可以完整完成；缺口未补齐时仍为有限结果。前端依据最终检查显示状态，原始失败事件保留，不改写历史。

## 验收方法

离线回归使用禁止联网的测试环境，验证同步/异步实际框架调用、并发、预算、证据、错误阶段、取消和前端状态。真实服务回归单独运行，使用生产 ASGI 生命周期与配置中的模型、Tavily，数据库和结果隔离到 output，不启动监听端口或修改原有会话。

固定六类问题：纯计算、武汉明日天气、Python 3.11 官方文档、四对象对比、精确不存在型号、原始华为手表选购问题。脚本为 tests/manual/search_regression.py 和 tests/manual/system_regression.py；不通过 pytest 自动调用真实收费服务。

验收分别记录运行检查与功能检查。完整资料类回答必须有真实搜索、通过检查的证据、最终 complete 检查及各题必要要点。此前失败后已恢复的尝试不否定完整答案，但未检查的最终文字、只有安全提示的结果都不能算完整成功。不存在型号允许明确无法核实，必须保留精确对象并实际尝试检索，不能改成相似型号或编造价格。
