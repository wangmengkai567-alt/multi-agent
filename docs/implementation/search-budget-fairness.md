# 检索任务公平额度与定向补查修复

后续单对象检查范围、失败收尾和取消日志修复见 [search-scope-fix.md](search-scope-fix.md)。

## 原因

复核轮次 f0f7bdbf-71e3-4093-8666-78a8e130e41a，两个联网子任务确实分别处理尚界 Z7 与小米 SU7。旧版整轮共享的两次额度都被 Z7 子任务消耗，SU7 没有成功检索；Z7 的上市日期补查也在执行前被额度拦截。其中一个初检还转向了尚界 H5。该轮原始返回及给模型的片段均没有目标上市日期，不能归因为片段截断，更不能据此宣称网上没有该信息。

## 当前行为

- 以规范化任务说明和已通过检查的内部数据库结果版本标识逻辑检索任务。相同说明的并发执行会被拒绝；已完成任务重新委派不会刷新额度。语义相同但改写说明的任务不做语义去重，仍受子任务数量及整轮硬上限约束。
- 每轮最多接纳三个检索任务。普通任务各有两次初检，调研任务各有六次；每个任务只在检查指出内容缺口后开启两次补查。整轮普通/调研上限分别为 12/24，配置校验确保可覆盖全部任务及其保留补查次数。额度是上限，不是要求用满。
- 仅缺引用或格式时复用已有证据整理，不重新搜索。内容补查要求围绕缺口定向查询，并使用 Tavily advanced 检索；初检继续使用 basic。实际网络重试复用原调用槽位，普通重复调用 ID 不能绕过计数。
- 质量检查失败只关闭相应检索任务，不连带禁止其他独立问题。模型依赖超时仍有本轮助手熔断，防止主助手不断重跑失效依赖。
- 原始用户问题同时提供给执行器和检查器。主助手扩写的可选调查项不自动成为硬性条件；核心事实缺依据、冲突未解及无依据断言仍不能通过。
- 检查启用可配置的 JSON object 模式，并保留严格结构校验及一次格式修复。检查结构失败不伪装成网络检索失败，也不自动放行。
- 额度耗尽后的整理请求使用新的消息上下文，传入本任务真实证据、原始需求、修订要求及已经读取的技能正文，不继续带旧工具调用历史。移除工具并发送 tool_choice=none，执行层另行拦截超额请求。网页正文在所有查询间共用 12000 字符的模型预算，保留头尾和截断标记；URL、实际请求参数、调用 ID 及完整原始存档保留。此预算不代表完整模型请求总字符数。
- 界面区分“当前请求未执行”与已经获准的并发请求，避免把子任务初检额度用尽误报为整轮没有剩余额度。
