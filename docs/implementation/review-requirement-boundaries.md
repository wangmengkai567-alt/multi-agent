# 检查条件与子任务边界修复

后续正文获取修复已完成两道原题的真实功能验收，见 [网页正文与四对象对比修复](web-page-evidence-fix.md)。本页下方的失败结果与“剩余问题”保留为前一阶段历史记录，不代表后续修复的最终状态。

## 问题与处理

原始需求只要求引用 Python 官方文档，主助手分派时却可能补上“优先 Glossary”“逐字英文原文”等细节。原实现让检查器自行输出自由文本补查指令，并将它直接交回执行器，导致方法偏好被升级为必需条件。

本次把两个约束分别保留：原始用户需求限定验收条件，分派说明限定当前子任务负责的对象。原始问题不会成为每个子 Agent 都必须完整执行的任务。

- 每次检查创建独立、不可变的 `ReviewContract`，保存原始需求、当前分工、当前答复和本任务成功工具记录的文本快照。不把本次状态保存在共享检查器实例上。
- 模型返回结构化阻塞项：缺失必需内容、无依据断言或证据冲突。缺项必须定位原始需求和当前职责；断言必须定位当前答复；冲突还必须定位当前任务的成功工具调用及原始片段。
- 程序从原始需求提取引文候选，在当前调用的严格 JSON Schema 中限定 `requirement_quote` 的可选值，并在检查输入中提供同一候选集。候选不是分派给所有子任务的全局清单。每次调用生成独立 Schema，不污染共享检查器或其他任务。
- 校验不通过的新增条件不会进入修订指令。如果同一检查含有有效事实问题，则只修订有效问题；如果全部问题无法定位，只复查检查器一次，仍无效则明确标记检查未完成，不自动放行，也不因此重搜。
- 复查反馈区分原始需求引文与只出现在分工说明中的引文，并保持原分工不变，帮助检查器纠正具体的条件来源错误，而不是仅收到一个笼统校验错误。
- 补查指令由程序根据通过定位校验的问题生成。未要求的附加断言可以删除，不强迫为保留附加细节而扩大调查。
- 检查输入不再重复加入包含完整任务的上下文包装，仍单独保留当前分工。事实检查、真实来源校验和服务端必需工具检查继续执行。
- 执行阶段也采用同一契约：原始需求决定必需事实，分工说明决定负责对象。额度用完后的汇总输入在顶层保留这两个字段，避免原始需求被埋在嵌套字符串中。主助手不能为自己附加的方法要求重复派工，未覆盖的其他用户指定对象仍可独立执行。
- 被否决答复的引文只用于当前子任务修订和持久化检查记录。默认返回主助手的失败报告不再包含这些数值、链接和原句，避免主助手将检查意见重建成事实。显式配置的未检查结果降级策略保留原有语义。
- 最终答复修订收到程序提取的可引用来源目录及应删除链接，来源只来自通过检查的任务和用户原先提供的链接，不从失败任务借用来源。

## 隔离和边界

未改变每个子任务的工具权限、工作目录、Skill 可见性、搜索额度和生命周期。`active_call`、证据收集器和搜索额度仍按调用隔离；同一子任务仅在自身受控修订中保留自己的搜索证据。原始分派说明在修订期间固定，不用修订消息替代下一次检查的职责边界。

父任务只有在最终综合阶段才汇总已通过检查的资料。子任务检查器不会读取整轮搜索任务的证据目录，即使另一个并行任务已经成功，也不能引用其调用 ID 证明本任务的断言。

引文定位能够约束条件来源，并不等于程序能够完全理解自然语言要求。条件是否已满足、材料是否足以支撑某个结论，仍需要模型判断；保留有界复查和失败状态，不能保证模型永不误判。
