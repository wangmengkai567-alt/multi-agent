日期：2026-10-24（Asia/Shanghai）。

## 范围

用户确认本次实施上一轮方案“实施顺序第①项：技能接口统一”。仅修改技能注册元信息、任务请求校验、技能目录接口和页面选择逻辑；其余路由、证据协议、认证及资源归属修复不并入本阶段。

## 改动

- agent/runtime/skills.py：用不可变 SkillDefinition 注册显示名称与原有只读文件集合，派生 SKILL_FILES / SKILL_IDS。现有五个 ID 和资源位置保持一致。
- 同一模块以 BUSINESS_REQUIRED_SKILLS 定义业务模式的必需技能；服务端校验和目录接口均读取这一定义。
- GET /api/skills：返回 skills（id、label）、max_selected 和 required_skills；不返回技能正文、本机路径、模型配置或凭据。
- POST /api/task：skill_ids 的数量上限由注册表长度派生，允许现有五项合法技能组合。原有严格字符串类型、未知 ID 和重复 ID 拒绝逻辑保留。ordinary 的省略、null 或空列表仍表示没有显式选择；internal_external 必须包含所需技能。
- api/static/index.html / app.js：移除固定的五个复选框及名称表，由目录生成选项、显示名称和模式所需技能。模式必需项自动勾选并锁定，切回普通模式后可由用户调整。
- 目录未就绪或加载失败时禁止提交新任务，并显示明确错误和重试入口，不使用另一套本地默认目录。历史读取和既有任务状态同步独立启动，目录失败不会因此取消或阻止查看既有任务。未知历史技能仅显示记录中的 ID。
- 更新页面脚本版本参数，使刷新后的页面请求新脚本。

技能选择继续经过各专家 allowed_skill_ids 的范围限制。没有新增技能、工具或默认选择；没有放宽文件只读、网络、预算或事实审核权限。不涉及数据库迁移和 checkpoint 协议变化。
