## 根因及实际改动

此前只有搜索工具，缺少直接读取网页正文的能力。搜索引擎即使用版本路径定向查询，也可能返回旧版或其他语言；短摘要不足以支持四种对象的全部维度。代码还在压缩证据时优先选择 content，忽略同时返回的 raw_content。模型据此补写英文原文或版本标签，事实检查随后失败。

1. 加入 `read_web_page(url, query)`，使用已安装 Tavily 客户端的 Extract 接口，读取与当前问题相关的真实正文段落。模型可验证同一已检索官方域名下的准确版本路径，不再只能反复检索摘要。原始响应和失败页面均保存，失败页面不产生可引用来源。
2. 工具展示、证据收集、检查和最终来源检查均识别正文读取结果。优先使用实际 raw_content；正文片段优先获得上下文额度，避免再次被截为发现页面时的千字摘要。整段上下文仍有明确上限，完整工具响应仍保存为原始证据。
3. 搜索额度与正文读取额度分别控制。每个子任务最多读取 3 次，跨本任务修订不重置；整轮最多 3 个检索子任务，正文读取也受工具总预算、超时与取消限制。搜索额度用完后只保留正文工具，不允许新搜索；全部额度用完后只整理证据。
4. 正文读取只允许当前子任务实际取得的公共域名，或用户原先提供的 URL。域名校验不读其他子任务的来源目录；证据和额度继续按调用隔离，只有主助手最终综合才汇总已通过的资料。
5. 前置校验使用工具 Schema 规范化后的参数，避免工具接受的数字字符串、数组字符串被策略层错误拒绝。未知字段保留给策略继续拒绝，不借此绕过 task 参数、SQL 或文件权限规则。
6. 最终整理限制无需求的附加引文、函数示例与版本标签；检查仍核对答复自行断言的事实，有误的可选补充应删除，不升级为必须补查的条件。此前原始需求与分工边界的定位校验继续保留。

没有放宽事实或来源检查，没有把失败任务的引文交给主助手充当事实，没有硬编码两道题的答案，也没有修改真实验收脚本或判定标准。

接口依据：[Tavily Extract 官方文档](https://docs.tavily.com/documentation/api-reference/endpoint/extract)。
