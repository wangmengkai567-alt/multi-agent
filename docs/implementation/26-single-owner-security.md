# 第四部分：单人认证与资源归属

本阶段实现单人使用的登录、持久所有者、按资源授权和前端登录流程。没有创建、修改或运行测试，也没有启动服务、读取真实 `.env`、调用模型、执行迁移或修改生产数据库。

## 认证协议

- `APP_ACCESS_PASSWORD` 是独立的高熵访问口令，32–1024 字符，至少 12 种字符；拒绝复用环境中已配置的服务 API Key 或 MySQL 口令。用密码管理器生成，不能拿模型密钥代替。
- 服务端使用随机盐和 scrypt 保存口令校验值。修改口令并重启会撤销旧登录会话，持久所有者及其任务不变。
- `POST /api/auth/login` 只接收 JSON `password`，要求精确的 `Origin` 与 `X-Login-Intent: login`。口令验证错误不回显输入，不使用包含原始输入的模型校验错误。每分钟最多五次口令验证，计数持久化到 SQLite。
- 登录生成 256 位随机会话令牌；数据库保存其 SHA-256 摘要、所有者、CSRF 值和固定到期时间。Cookie 为 HttpOnly、SameSite=Strict；HTTPS 来源启用 Secure。URL、localStorage、agent 上下文和任务事件均不携带登录凭据。
- `GET /api/auth/session` 返回内存使用的 CSRF 值和到期时间。所有业务 API 均要求有效 Cookie，所有修改操作另要求精确 Origin 和 `X-CSRF-Token`；上传、取消、恢复、创建会话、退出均覆盖。
- `POST /api/auth/logout` 撤销当前登录会话并删除 Cookie；不会取消任何后台任务。
- WebSocket 在 accept 前校验会话、Origin、线程和运行归属。发送前再次验证会话；独立监听到期和撤销，空闲连接也会关闭。关闭与发送串行处理。

## 资源归属

运行库 schema 为 8，任务库 schema 为 1。两个库保存相同的唯一 `owner_id`、`migration_id` 与迁移完成标记。

`threads` 持久记录所有者；运行记录继承线程所有者，事件、子任务、查询结果继承运行归属。运行库读写入口检查归属，启动和迁移完成前检查子记录与父运行的对应关系。

后台任务单独持久化 `resource_owner_id`，提交时从父运行推导，并验证订阅运行在同一线程。任务库原有 `owner` 继续只表示工作进程租约，不作为用户身份。后台研究执行线程由服务端从已授权的任务创建，checkpoint 18 同时绑定 owner、thread 和逻辑任务；恢复还检查源运行归属。

`POST /api/threads` 生成已归属线程，用于先上传再提交任务。`POST /api/task` 未提供线程时也由服务端生成；提供线程时只能引用已经归属的线程。`POST /api/upload` 不再接受任意线程作为新资源目录。

公开文件接口统一为：

| 接口 | 规则 |
| --- | --- |
| `GET /api/runs/{run_id}/files` | 查询已授权运行的文件列表；只返回相对引用与下载 URL |
| `GET /api/runs/{run_id}/files/download?path=answer.md` | 从运行记录中的工作目录解析相对文件；拒绝绝对路径、越界和重解析点 |

普通运行工作目录为 `session_{thread}/run_{run}`；后台研究目录从已归属 job 映射为 `background-jobs/{task}`。PDF 转换从父运行推导发布目录，持久 payload 不再接受绝对 `work_dir`。生成答案、后台任务结果、前端文件面板使用同一下载协议。

旧 `/api/download`、`/api/files` 和 `/output/{path}` 已删除，不保留兼容入口。历史答案及事件原文保留，其中旧链接会失效；可从登录后的运行文件面板取得新链接。页面后台任务列表重新查询权威任务接口，不使用历史事件中的旧文件地址。没有对应运行记录的目录保留在磁盘，禁止全局枚举或按路径开放。独立脚本生成但未登记到运行库的文件也不通过 HTTP 暴露。

## 前端会话

未登录时只显示登录表单，确认会话后才读取技能目录、运行历史和后台状态。收到 401 或会话到期后，关闭 WebSocket、清除轮询定时器和已显示的私有内容；重新登录后按保存的运行 ID 向服务器恢复视图。异步请求绑定前端会话代次，旧会话响应不覆盖新状态。浏览器页面间只广播登录状态变更，不广播令牌或口令；另一页面登录后重新获取 CSRF 状态。

## 部署与首次迁移

1. 停止所有旧服务、后台工作进程和独立任务脚本。新的服务与迁移命令使用同一进程文件锁，但旧版本及独立脚本没有该锁，必须先自行停止。
2. 在真实 `.env` 中设置独立随机 `APP_ACCESS_PASSWORD`。默认使用 `APP_ORIGIN=http://127.0.0.1:8000`、`APP_BIND_HOST=127.0.0.1`、`APP_BIND_PORT=8000`、`APP_SESSION_SECONDS=43200`。浏览器必须使用该精确地址；`localhost` 与 `127.0.0.1` 不能混用。
3. 在项目目录手动执行以下命令。本轮没有执行。

```powershell
uv run --offline --no-project --python .venv\Scripts\python.exe python -B -m api.migrate_security
```

迁移首先使用 SQLite backup API 将两个库各自备份至 `data/security-backup-日期时间/`，缺失的库在 manifest 中标明；备份全部完成后才开始改库。两库各自使用事务，不宣称跨库原子提交。历史运行和上传线程明确归属到唯一持久所有者，任务资源归属从父运行核对；转换输入、预算、状态、取消、已用次数和租约恢复字段不会重置。旧绝对转换目录及产物引用只在离线迁移中转为已授权的相对引用。

两个库都通过身份、父子归属和工作目录核查后才标记完成，并写出 `data/security-resources.json` 的资源映射。中断后重新运行命令，继续使用运行库中已经建立的身份与迁移 ID，不重新分配所有者；每次尝试先产生独立备份。发现孤立任务、父子身份不一致或目录越界时停止，不猜测归属、不删除记录。运行时不执行迁移、不接管遗留数据；任一库版本、完成标记或归属不一致时拒绝启动和恢复任务。

旧 checkpoint 17 缺少所有者绑定，不改写其内容、不重置预算重新续跑；保留原文件并将恢复明确中断，需新建任务。旧模型生成结果的语义协议没有变化，审核缓存版本不变。

4. 迁移成功后启动并登录：

```powershell
uv run --offline --no-project --python .venv\Scripts\python.exe python -B api\server.py
```

服务只绑定回环地址，无通配 CORS，公开 `/docs`、`/redoc`、`/openapi.json` 已关闭。远程使用需在同机部署 HTTPS 反向代理，将 `APP_ORIGIN` 设置为精确 HTTPS 来源，并保留对应 Host 与 WebSocket Upgrade；后端仍保持回环监听。应用不信任转发头，不依据客户端伪造的协议决定 Cookie 安全属性。代理层也不得记录 Cookie、请求体或带凭据的 URL。

## 恢复与边界

迁移失败时保留原始文件和已打印的双库备份，先保持服务停止。常见中断可直接重跑迁移；归属核查失败则应先查明冲突，不能修改 owner 值强行放行。

需要还原时，应在所有进程停止后，将当前 `data` 目录整体另存，再成对恢复同一次备份中的 runs/jobs 数据库，并配合迁移前代码；避免将旧 WAL/SHM 与恢复的主数据库混用。manifest 标记原本不存在的库，不能把它误当成已经备份的空库。迁移没有移动或删除 output/updated 文件，不需要回写这些文件。

本阶段只完成静态校验，不代表已实测登录、会话撤销、迁移中断恢复或真实业务链路。实际 `.env` 由使用者配置，生产库尚未升级；这些操作完成前，新服务会按设计拒绝启动。
