## ③ 已实施

- 移除同步工具的 daemon Thread/Future 超时包装。工具作用域负责协作取消，真正阻塞的数据库、文档解析、Tavily HTTP 和 Word 转换在独立工作进程执行。
- 工作进程只接收固定操作 JSON，不序列化任意处理器、模型、运行上下文或数据库连接。数据库凭据和搜索密钥仅通过匿名管道传入，不出现在命令行或检查点中。
- Windows 先挂起创建进程，复制 Popen 持有的原始句柄，归入非 breakaway Job Object 后恢复。超时或取消时终止并等待整个作业对象清空；未能回收时终止运行，不释放其并发占位。
- 仅保留有界 RPC 管道读写线程，工作进程回收后等待管道线程退出；并发上限为 8 个工作进程。
- 文档有界读取保留原始字节、摘要和定位信息；工具证据、Skill 快照和模型反馈仍在父进程登记。
- 搜索工作进程在 HTTP send 前等待父进程确认。父进程先扣账、写传输记录并 fsync，再允许发送；保留 HTTP 状态、Retry-After 和超时分类，禁止一个 attempt 多次发送。
- Word 从启动时就是作业对象的子进程，不通过 DispatchEx 在 RPCSS 外部激活。只绑定临时 HTML 的运行对象；父进程确认 Word 所属 PID 属于本次确切的作业对象后，才允许修改应用属性、保存或退出。窗口隐藏启动，不接管用户已有 Word。
- PDF 工具具有显式异步入口，直接等待持久化提交；取消会作用于实际等待的协程。同步入口等待失败时取消提交 Future。

## ④ 已实施

- 在业务模型请求前检查当前锁定契约需要的能力。普通解释不要求数据库、联网或 Word；显式数据库任务及选中的数据库专家检查只读配置、连接、授权和允许表。
- 搜索检查密钥和 SDK 可加载性；这不代表已经在线验证服务商认证或可用额度。
- 按实际上传文件检查解析依赖；PDF 交付检查 Markdown、pywin32 和 Word 注册。缺失的可选 SDK 不再因全局导入而阻断不相关业务。
- 不可用能力通过 capability_preflight 持久化事件披露。数据库不可用时，既有内部/外部分析流程可据此进入明确披露缺口的外部分析，不伪造数据库结果，也不把整个任务标为已完成。
- 多个文件中只有一种解析器缺失时保留其余读取能力；read_document 的实际参数 schema 只列出可读取的绑定文件，调用准入再次检查。无法读取的必需文件继续算作缺口。
- 缺失强制 PDF 引擎时在业务生成前失败，不替换引擎或假装完成文件交付。

## ⑤ 已实施

- 当前检查点协议为 24；仅验证当前协议恢复，没有执行旧任务续跑诊断，也没有新增兼容路径。
- 内部执行检查点使用精确 JSON 保存，公开审计文件仍脱敏；避免脱敏改变契约输入或交付摘要。检查点字段使用明确白名单，保留身份、契约、参考时间、预算、采集账本、技能快照、计划及交付状态。
- 恢复保留原参考时间；已发送与不确定发送继续占用预算。校验调用计数、供应商账本分类、传输序号和重复发送身份，拒绝预算不足或账本不一致的恢复。
- 已执行过的任务若当前检查点缺失，拒绝自动重新开始，不能把调用预算归零。首次后台执行则在业务开始前初始化交付保留额度。
- result_saved 事件与不可变结果一起提交，记录稳定 task_id、scope_version 和任务定义摘要。恢复时从数据库当前结果与原始证据校验已审核事实，补齐比检查点更新的结果；关闭已结束分支，只释放未使用预留，不退回已扣调用。
- 数据库结果、原文摘要、任务身份或来源不一致时停止恢复，不覆盖原检查点来掩盖问题。
- 不重放旧 LangGraph 节点，不直接把旧 AIMessage 当成最终答复。新图执行帧从锁定目标、已核验事实、原始义务、剩余缺口、稳定任务 ID 和剩余预算继续，仍经过原有终审与交付检查。
- 保留现有交付动作去重：已接受结果校验文件摘要后复用；未确认动作禁止自动重放。
- 转换使用 input.md、stage.pdf、publication.json。发布前持久化源摘要、输出路径和 PDF 摘要；崩溃发生在原子改名后、数据库提交前时可完成对账，不重新转换。文件丢失或变化时拒绝自动重做。
- 后台租约续期检查实际更新行数，续期操作有时限；失去租约时停止上下文并取消执行任务。
