# 顺序②：必需分支与最终交付资源预留

实施日期：2026-10-26。

## 范围与依据

修复单个专家耗尽整轮资源、挤占其他必需分支和文件交付额度的问题。保留现有工作区状态，不新增或修改测试文件，不运行三道真实业务验收题。只使用 git status；按项目限制不运行其他 Git 命令。

参考 Codex 固定提交 `970111f6cb62cc02fe36a82ea7d71b37a2889c97` 的[共享预算账本](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/core/src/rollout_budget.rs)：主、子执行共享记账和硬上限。本项目的分支最低额度、报告与文件交付预留属于业务适配，上游没有可直接复制的同名交付流水线。

## 最终行为

- 契约锁定前，原子准入已知必需来源、绑定材料和最终交付；资源不足时返回具体的 reserve_exhausted 或 time_exhausted，不开始无法准入的工作。
- 研究计划 initialize / append 成功前，为各任务保留协调与委派、最低采集、事实报告和审核额度。正式计划替换搜索来源占位预留，避免重复计算。拒绝时需求、对象、计划和预留同时回滚。
- 采集只能使用自己的最低额度及全局未预留额度；不能消耗其他分支的最低额度、自己的报告审核额度和终稿额度。触及保护边界时只结束该专家采集，其他分支仍可调度。
- 专家报告预留在委派时转移到既有报告/修订账本，不双计；可选证据修订按剩余调用和时间重新准入。删除不再使用的 revision_floor 机制。
- 追加研究任务继承对象的搜索额度；搜索总额度还要容纳尚未开始的对象。更换描述、任务 ID、重新委派及检查点恢复不能刷新已消费预留。文档和数据库专家按稳定工作身份区分不同分工；新分工重新准入，沿用全局累计调用计数。
- 进入终稿时释放不再执行的采集预留；这些未执行工作仍保留为真实覆盖缺口，不改变已审核事实或原始需求。
- 预留不计作已消费。实际模型、审核及工具调用仍原子计入同一全局账本，并保留原权限、路径、来源、正文摘要和文件字节一致性校验。

## 交付额度

| 步骤 | 受保护额度 |
| --- | --- |
| 终稿综合及一次修订 | main_model = 2 |
| 直接答复的终审与复审 | review = 2，retry = 1 |
| 有证据答复的终审与复审，含两轮各一次审核格式修正 | review = 4，retry = 3 |
| 纯文本 | 文件工具 = 0 |
| Markdown | 文件工具 = 1：生成 Markdown |
| PDF | 文件工具 = 2：生成 Markdown、转换或提交 PDF 转换 |

文件预留只由通过程序授权的真实交付工具消费。主模型普通采集、专家工具、上下文摘要或手工拼接调用不能取得交付额度。PDF 转换提交成功与转换完成仍沿用原有 artifact 状态，并不因预留存在而提前宣称完成。

## 时间与配置

顺序②的首次实现曾引入固定 10 秒时片；该设计会截短原有请求时限，已在[后续修正](29-budget-control-followup-correction.md)中删除，不再存在 reserved_model_seconds / reserved_tool_seconds 配置。

单次模型与工具请求沿用 request_seconds / tool_seconds 上限，当前分别为 60 / 25 秒，同时受整轮剩余时间约束。调用次数为所有已准入任务保留；时间则为已启动专家的报告和审核，以及终稿至少一轮综合、审核和所需文件工具预留。未启动分支和可选修订不作为已开始工作重复占用时间；启动专家及安排修订时重新检查剩余时间。

采集只能使用扣除上述后续步骤和 shutdown_seconds 后的剩余时间；交付保护时间至少为 finalize_seconds。task 委派包围子步骤，不额外重复计算整段执行时间。排队和重试等待同样检查保护边界；未发送的研究请求按原规则退还调用额度，并且只退还一次对应的最低分支额度。预留保障执行机会和预算隔离，不保证取得外部事实或通过真实性审核。

## 检查点

当前检查点版本为 21，保存 capacity_reservations、专家工作身份、报告预留与实际调用计数。恢复时校验记录、阶段、计数、预算和剩余时长；已消费预留不会重新补足。缺失或损坏的必要记录拒绝恢复。旧版检查点保留原文件，按现有规则中断，不自动迁移或续跑；未结束的旧任务需重新发起。

## 首次实现的历史验证记录

以下 25 项为后续修正前的验证记录，未覆盖计划工具额度、不同文件连续委派及慢于 10 秒的报告请求，不能作为当前版本的验收依据。当前验证结果见[后续修正](29-budget-control-followup-correction.md)。

未调用真实业务模型、Tavily 或 MySQL；所有临时执行验证通过 stdin 运行，结果目录在系统临时目录，未写入测试文件。

25 项定向场景通过：

1. 纯文本、Markdown、PDF 三组场景：一个文档分支采集到保护边界后停止，其他三个已批准研究分支仍拥有最低执行额度，随后完成交付准入。Markdown 使用真实写入工具；PDF 使用真实两个工具入口和转换桩，仅验证预算、路径及交付控制，不验证 Word 转换或 PDF 排版。
2. 超额计划原子回滚、请求时限保护、恢复不刷新额度、换 ID 重委派拒绝、终稿释放未开始分支、损坏检查点拒绝、并发准入不能透支、硬上限仍终止运行。
3. 研究请求发送前失败的额度退还幂等；同步和异步排队在保护边界退出，并清理等待票据。
4. 同步和异步生产专家工厂执行链：连续 grep 导致预留边界收尾，独立事实报告、真实语义审核、终稿审核及实际 Markdown 写入继续完成。驱动模型固定协议响应，报告仅披露缺口，没有伪造事实。该验证证明控制链，不能替代真实模型业务验收。
5. 追加支持任务不得刷新已耗尽的对象搜索额度，拒绝时计划和需求保持原状态。

8 组已有回归检查共 101 项，与仓库外修改前源码及配置快照对照，修改前后均为 **55 通过、39 失败、7 个夹具错误**，节点结果完全相同。失败涉及旧接口/证据协议、检查点归属约束、未准备身份认证或安全迁移的 API 夹具、旧 JobService 参数等；没有通过修改测试、迁移实际业务数据库或放宽权限使其通过。该结果不代表全套历史检查通过。

静态、格式、AST、UTF-8/BOM、CRLF 和空白检查在交付前执行。项目仅允许 git status，因此未运行 git diff --check；使用逐文件字节与行检查核对空白和换行。
